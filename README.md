# Second-Year Study Hub

## Supabase authentication setup (Cloudflare version)

The Cloudflare site at `https://second-year.mehtajeeval1.workers.dev/` uses Google OAuth through Supabase. The static GitHub version keeps its existing email entry flow. The old browser-side administrator form is removed because it cannot securely approve users; existing browser-local approvals remain readable in the static version. No deployment is part of this change.

1. Create a Supabase project. In **Project Settings → API Keys**, copy the **Project URL** and the **publishable key** (begins with `sb_publishable_`). Put only these two public values in [`assets/study-hub-config.js`](assets/study-hub-config.js). Never place the service role/secret key, database password, or Google client secret in a repository or browser file.
2. In the Supabase **SQL Editor**, run [`supabase/migrations/20261009000000_study_hub_auth.sql`](supabase/migrations/20261009000000_study_hub_auth.sql). Review the 35 existing approved emails first. Students added only in one browser's old admin panel are not in this list; add them in Supabase before switching that site's login. To approve someone later, insert their lower-case UNE email and display name into `public.study_hub_approved_emails` using the Supabase dashboard. To revoke access, delete their row there. The table's row level security allows a signed-in student to read only their own approval.
3. In Google Auth Platform, create a **Web application** OAuth client. Add `https://second-year.mehtajeeval1.workers.dev` as an authorized JavaScript origin. Add the Supabase callback URL shown on **Authentication → Providers → Google** as the authorized redirect URI. Store Google's client ID and client secret only in the Supabase Google provider settings. Enable Google there.
4. In Supabase **Authentication → URL Configuration**, set the Site URL to `https://second-year.mehtajeeval1.workers.dev/` and add that exact URL to the redirect allow list. Add specific preview or local URLs only when testing them. The JavaScript SDK persists and refreshes sessions, and handles the OAuth return URL.
5. Test with an approved `@une.edu` Google account, an unapproved `@une.edu` account, and a non-UNE account before connecting this branch to production. Check sign-in, reload, logout, and the study/quiz flows.

The feature branch includes a minimal `wrangler.jsonc` with a `previews` block so Cloudflare can build an isolated Worker Preview. The preview URL also uses Google sign-in. Add the exact preview URL to Supabase's redirect allow list before testing OAuth there; the Google provider callback URL remains the same. Keep the Cloudflare production branch set to `main`, and leave the build command empty so only the preview command runs on this feature branch.

The browser stores the authenticated user's Supabase UUID as `AUTH_STATE.user.id`. `window.StudyHubAuth.getUserId()` exposes the UUID for later progress sync. The migration creates an RLS-protected profile table keyed by the same UUID, but Phase 1 does not write quiz progress or AI keys. Future data tables must enforce `auth.uid()` ownership in database policies. Keep BYOK provider secrets out of public files and use a protected server flow when that feature is built.

**Security limit:** Study Hub and its quiz files are currently static assets. A browser login overlay does not prevent someone from requesting their URLs directly. The Supabase approval check controls the app UI and database access; protecting the study content itself requires a Cloudflare Worker or another server-side gate in a later phase. The GitHub static version remains publicly accessible by design. The obsolete standalone Study Hub page redirects to the main OAuth entry on Cloudflare. Existing passwords embedded in the two Study Hub pages were removed; rotate them if they were reused elsewhere.
