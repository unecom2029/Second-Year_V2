# Second-Year Study Hub

## Supabase authentication setup (Cloudflare version)

The Cloudflare site at `https://second-year.mehtajeeval1.workers.dev/` uses Google OAuth through Supabase. The static GitHub version keeps its existing email entry flow. The old browser-side administrator form is removed because it cannot securely approve users; existing browser-local approvals remain readable in the static version.

1. Create a Supabase project. In **Project Settings → API Keys**, copy the **Project URL** and the **publishable key** (begins with `sb_publishable_`). Put only these two public values in [`assets/study-hub-config.js`](assets/study-hub-config.js). Never place the service role/secret key, database password, or Google client secret in a repository or browser file.
2. In the Supabase **SQL Editor**, run [`supabase/migrations/20261009000000_study_hub_auth.sql`](supabase/migrations/20261009000000_study_hub_auth.sql). Review the 35 existing approved emails first. Students added only in one browser's old admin panel are not in this list; add them in Supabase before switching that site's login. To approve someone later, insert their lower-case UNE email and display name into `public.study_hub_approved_emails` using the Supabase dashboard. To revoke access, delete their row there. The table's row level security allows a signed-in student to read only their own approval.
3. In Google Auth Platform, create a **Web application** OAuth client. Add `https://second-year.mehtajeeval1.workers.dev` as an authorized JavaScript origin. Add the Supabase callback URL shown on **Authentication → Providers → Google** as the authorized redirect URI. Store Google's client ID and client secret only in the Supabase Google provider settings. Enable Google there.
4. In Supabase **Authentication → URL Configuration**, set the Site URL to `https://second-year.mehtajeeval1.workers.dev/` and add that exact URL to the redirect allow list. Add specific preview or local URLs only when testing them. The JavaScript SDK persists and refreshes sessions, and handles the OAuth return URL.

   If Google sign-in returns to `http://localhost:3000/`, the production URL is missing from Supabase's redirect allow list or the Site URL is still set to the default localhost value. Add the exact production URL above to the allow list and change the Site URL; no code or Google callback URL change is needed for that redirect. The browser client uses PKCE so future OAuth redirects carry a short-lived authorization code rather than access and refresh tokens in the URL.
5. Before inviting students, test with an approved `@une.edu` Google account, an unapproved `@une.edu` account, and a non-UNE account. Check sign-in, reload, logout, and the study/quiz flows.

The repository includes `wrangler.jsonc` with a Worker entry point and a `previews` block so Cloudflare can build isolated Worker Previews. Keep the Cloudflare production branch set to `main`, the build command empty, and the deploy command `npx wrangler deploy`. Preview URLs also use Google sign-in. Add an exact preview URL to Supabase's redirect allow list before testing OAuth there; the Google provider callback URL remains the same.

The browser stores the authenticated user's Supabase UUID as `AUTH_STATE.user.id`. `window.StudyHubAuth.getUserId()` exposes the UUID for later progress sync. The migration creates an RLS-protected profile table keyed by the same UUID, but Phase 1 does not write quiz progress or AI keys. Future data tables must enforce `auth.uid()` ownership in database policies. Keep BYOK provider secrets out of public files and use a protected server flow when that feature is built.

## Course file access and printing

On Cloudflare, `worker/index.js` runs before static assets. It serves the sign-in page and its visual assets publicly, but requires a valid, signed Supabase Google session for course notes, quizzes, images, and PDFs. After Supabase verifies the student and the approval table, the browser sends its access token to `/api/session`. The Worker verifies its signature against Supabase's public signing keys, checks the approval row, and sets a short-lived Secure, HttpOnly cookie. The browser refreshes that cookie when Supabase refreshes its session and clears it on logout. A direct course link redirects unsigned visitors to Study Hub and returns them to the same page after sign-in. No service role key, Google secret, or new SQL migration is needed for this gate.

The unreleased Cardio summative review remains restricted to its existing approved account on Cloudflare. All standalone HTML notes and quizzes in OMK, OCS, Neuro, OMM, Psych, and quizbuilder suppress browser printing. This is a deterrent: browsers cannot prevent screenshots, copying, developer tools, or printing a separately downloaded PDF. The static GitHub version and public repository remain accessible outside this Cloudflare gate. If the content must be confidential, remove it from public GitHub hosting and the public repository.

Test an approved student's first Google/Okta login from a direct note link, then refresh the note, open a quiz and its images, and log out. Also test an unsigned direct link and an unapproved account. The Worker tests run with `node --test tests/worker.test.mjs`.

The obsolete standalone Study Hub page redirects to the main OAuth entry on Cloudflare. Existing passwords embedded in the two Study Hub pages were removed; rotate them if they were reused elsewhere.
